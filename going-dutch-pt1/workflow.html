Workflow

The Karpathy Method

I adapted Andrej Karpathy's LLM Wiki pattern. In it, “the LLM incrementally builds and maintains a persistent wiki — a structured, interlinked collection of markdown files”.

The markdown files were organized in an application called Obsidian.

When a new source is added, the LLM “reads it, extracts the key information, and integrates it into the existing wiki — updating entity pages, revising topic summaries, noting where new data contradicts old claims, strengthening or challenging the evolving synthesis. The knowledge is compiled once and then kept current, not re-derived on every query.”

The pattern also calls for a schema that tells the model how to maintain the wiki; in this project, that document was a system of governance that divided authority between me and the agents, set a procedure for each kind of work, and required every result to be traced to recorded inputs and code.

Agents updated the wiki as evidence or decisions changed. A log kept track of project history.

How the repository was organized

The repository separated evidence, maintained knowledge and the machinery that produces results.

A wiki index linked to the maintained pages. A status page identified current results and open questions. The log recorded consequential changes.

Working rules and recorded choices

I established rules for evidence, reproducibility and authority. They distinguished agent implementation choices from choices requiring my judgment, and agents ingested them before performing tasks.

A configuration recorded inputs and settings. Each analysis retained its configuration, code revision and software versions. Changed analyses preserved earlier results.

A decision record held the choice, alternatives, evidence and consequences. I accepted choices that settled a result's meaning, and agents recorded and implemented them.

How evidence was acquired

I required literature searches before justifying research-based choices. An agent developed and executed each search strategy.

OpenAlex is a searchable catalog of scholarly works.

The agent queried OpenAlex and Crossref and saved queries, filters and responses.

The search log recorded screening criteria and reasons for retaining or rejecting sources.

Crossref supplied the publication metadata. It was queried using each publication's digital object identifier (DOI), and its responses were saved unchanged.

Papers went into the project's catalog and bibliography. Documents without DOIs used the publisher's record.

The full text of every cited paper was kept in the project, along with a plain-text copy so the LLM could parse it quickly. Each claim was checked against the text before the paper was cited.

The findings from each search went into a persistent wiki page.

Datasets were downloaded with scripts wherever possible. A wiki page recorded its provider, version, download date and license.

How citations reached the page

The page builder looked up each citation's saved bibliography entry. Its links showed authors and year, and bibliography entries used the metadata.

Crossref was queried with the paper's DOI, and its response was saved in the project:

A bibliography entry was built from that response and stored under a citation key, such as weikl2023:

The page's text cited the key at the end of a sentence: "I set the route criteria … as operationalized by Weikl and Mayer [@weikl2023]."

The code replaced each key with the authors and year from its entry, and linked it to the entry. A citation without a bibliography entry returned an error.

The bibliography listed every cited entry, formatted from the saved metadata. For instance, the weikl2023 entry became "Weikl, S. and Mayer, P. (2023). Data-driven quality assessment of cycling networks. Frontiers in Future Transportation, 4. https://doi.org/10.3389/ffutr.2023.1127742".

Method development

I set the route criteria from the Level of Traffic Stress framework (Mekuria et al. 2012; Furth et al. 2016) and the Dutch design manual for bicycle traffic (CROW-Fietsberaad 2016), as operationalized by Weikl and Mayer (Weikl and Mayer 2023). The agent translated these criteria into proposed rules. I evaluated their consequences before adopting them.

I required justification for choices about sources and street attributes. For these, the agent prepared literature findings and data comparisons. I then judged whether the evidence supported adoption.

Generated code and its checks

Agents wrote the analysis code. Each analysis kept its settings in a file separate from the code.

Agents also wrote tests. Each test ran the code on a small example with a known answer and checked that the code returned that answer.

Before using an input file, the analysis calculated its checksum and compared it with the recorded value. A checksum is a value calculated from a file's contents. A mismatch meant the file had changed, and the analysis returned an error.

When the code changed, earlier analyses were rerun to confirm that they still gave the same results.

Reproducing the analysis

The repository retains original inputs and documentation. It also holds cited works' full texts, and academic entries include publisher metadata.

A "current-results pointer" identifies the adopted analysis, and its record states the outputs, checks and limits.

Create the cycling-catchment environment from environment.yml. Run the legal-access analysis with python -m breda_pilot.adopted and that configuration; it reads only the two raw downloads its configuration names. Its metrics.csv supplies the result.

The reproduction instructions preserve exact commands and output locations.

Responsibility throughout the project

I organized the research and directed work throughout the project. I set the questions, working rules and review requirements. I also evaluated assumptions and required supporting evidence.

AI coding agents performed literature searches, coded, ran analyses, and maintained records. They also drafted prose and figures, which I edited extensively before finalizing. I reviewed all outputs and decided which analytical choices to accept.
